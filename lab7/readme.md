# Документация по интерфейсам и алгоритмам для lab5

## 220 — Архитектура

### Общая схема
- Клиент: статический фронтенд на HTML/CSS/JS (папка `lab5/frontend`).
- Сервер: FastAPI приложение (файл `lab5/app/main.py`).
- База данных: SQLite файл `lab5/app/social.db`.
- Файлы загрузок: директория `lab5/uploads`, раздается как `/uploads/*`.

### Потоки данных
1. Браузер загружает HTML из FastAPI (роуты `/`, `/login`, `/register`, `/posts/new`, `/posts/{id}/edit`, `/post/{id}`).
2. JS в браузере обращается к API через `fetch`.
3. FastAPI валидирует, работает с SQLite и возвращает JSON.
4. При загрузке изображений сервер сохраняет файл и возвращает URL вида `/uploads/имя_файла`.

### Основные компоненты
- **API слой**: маршруты FastAPI.
- **Сервисный слой**: функции в `main.py` для хеширования, токенов, работы с БД, сохранения файлов.
- **Хранилище**: SQLite таблицы `users`, `posts`, `comments`, `likes`, `media`, `sessions`.
- **UI слой**: страницы и скрипты фронтенда.

### Модель данных (кратко)
- `users`: имя, email, хеш пароля, аватар, дата создания.
- `posts`: автор, текст, изображение, даты создания/обновления.
- `comments`: пост, автор, текст, дата.
- `likes`: пост, пользователь, дата.
- `media`: связь загруженных файлов с пользователем или постом.
- `sessions`: токен сессии и пользователь.

## 230 — Сервисы

### Общие правила
- Базовый URL: `http://<host>:<port>`
- Формат ответов: JSON, если не указано иначе.
- Авторизация: `Authorization: Bearer <token>`.
- Если токен отсутствует или неверный — `401`.

### Модели (ключевые поля)
- **TokenOut**: `token: string`
- **UserOut**: `id: int`, `name: string`, `email: string`, `avatar_url: string|null`, `created_at: string`
- **PostOut**: `id: int`, `author_id: int`, `author_name: string`, `author_avatar_url: string|null`, `text: string`, `image_url: string|null`, `created_at: string`, `updated_at: string|null`, `likes_count: int`, `comments_count: int`, `liked_by_me: bool`
- **CommentOut**: `id: int`, `post_id: int`, `author_id: int`, `author_name: string`, `author_avatar_url: string|null`, `text: string`, `created_at: string`
- **PostDetailOut**: `post: PostOut`, `comments: CommentOut[]`, `liked_by_me: bool`

### POST `/auth/register`
Назначение: регистрация пользователя и создание сессии.
- Тело запроса: JSON
- Поля: `name: string(1..100)`, `email: string(email)`, `password: string(6..128)`
- Ответ 200: `TokenOut`
- Ошибки:
- `400` если email уже используется

Пример запроса:
```json
{"name":"Ivan","email":"ivan@example.com","password":"secret123"}
```
Пример ответа:
```json
{"token":"<hash>"}
```

### POST `/auth/login`
Назначение: вход и выдача новой сессии.
- Тело запроса: JSON
- Поля: `email: string(email)`, `password: string`
- Ответ 200: `TokenOut`
- Ошибки:
- `400` если email/пароль неверны

### GET `/users/me`
Назначение: получить профиль текущего пользователя.
- Авторизация: требуется
- Ответ 200: `UserOut`

### PUT `/users/me/avatar`
Назначение: загрузить аватар.
- Авторизация: требуется
- Тело запроса: `multipart/form-data`
- Поля: `file: image` (`.jpg|.jpeg|.png|.gif|.webp`)
- Ответ 200: `UserOut`
- Ошибки:
- `400` если файл не выбран или формат недопустим

### POST `/posts`
Назначение: создать пост.
- Авторизация: требуется
- Тело запроса: `multipart/form-data`
- Поля: `text: string` (не пустой), `image: image?`
- Ответ 200: `PostOut`
- Ошибки:
- `400` если текст пустой или изображение недопустимо

### PUT `/posts/{post_id}`
Назначение: обновить пост.
- Авторизация: требуется
- Path параметры: `post_id: int`
- Тело запроса: `multipart/form-data`
- Поля: `text: string` (не пустой), `image: image?`, `remove_image: bool` (по умолчанию `false`)
- Ответ 200: `PostOut`
- Ошибки:
- `404` если пост не найден
- `403` если не автор
- `400` если текст пустой или изображение недопустимо

### DELETE `/posts/{post_id}`
Назначение: удалить пост.
- Авторизация: требуется
- Path параметры: `post_id: int`
- Ответ 200: `{"status":"ok"}`
- Ошибки:
- `404` если пост не найден
- `403` если не автор

### GET `/feed`
Назначение: получить ленту постов.
- Query параметры: `limit: int(1..50)=20`, `offset: int>=0=0`
- Авторизация: опционально
- Ответ 200: `PostOut[]`
- Особенность: при наличии токена поле `liked_by_me` заполняется, иначе `false`.

### GET `/posts/{post_id}`
Назначение: детальная информация о посте и комментариях.
- Path параметры: `post_id: int`
- Авторизация: опционально
- Ответ 200: `PostDetailOut`
- Ошибки:
- `404` если пост не найден

### POST `/posts/{post_id}/comments`
Назначение: добавить комментарий.
- Авторизация: требуется
- Path параметры: `post_id: int`
- Тело запроса: JSON
- Поля: `text: string(1..2000)`
- Ответ 200: `CommentOut`
- Ошибки:
- `404` если пост не найден
- `400` если текст пустой

### POST `/posts/{post_id}/like`
Назначение: поставить лайк.
- Авторизация: требуется
- Path параметры: `post_id: int`
- Ответ 200: `{"status":"ok"}`
- Ошибки:
- `404` если пост не найден
- `400` если лайк уже поставлен

### DELETE `/posts/{post_id}/like`
Назначение: снять лайк.
- Авторизация: требуется
- Path параметры: `post_id: int`
- Ответ 200: `{"status":"ok"}`

### GET `/media/{filename}` и `/uploads/{filename}`
Назначение: раздача загруженных файлов.
- Ответ 200: файл (не JSON)
- Ошибки:
- `404` если файл не найден

### Алгоритмы и правила
- Хеш пароля: SHA-256 от `salt + password`, хранится как `salt$hash`.
- Токен сессии: SHA-256 от строки `user_id:random:timestamp:SECRET`.
- Проверка токена: поиск в таблице `sessions` и связанного пользователя.
- Валидация: email уникален, пароль минимум 6 символов, текст поста/комментария не пустой.
- Валидация изображений: только `.jpg`, `.jpeg`, `.png`, `.gif`, `.webp`.
- Feed: `JOIN` + подзапросы для `likes_count` и `comments_count`, сортировка `created_at DESC`.
- Комментарии: сортировка по возрастанию времени.
- Доступ: редактирование/удаление поста доступно только автору.

## 240 — UI

### Страницы
- **`/`**: основная лента + профиль пользователя + панель подробностей поста.
- **`/login`**: форма входа.
- **`/register`**: форма регистрации.
- **`/posts/new`**: создание поста.
- **`/posts/{id}/edit`**: редактирование поста.
- **`/post/{id}`**: детальный просмотр (реиспользует главную страницу).

### Основные элементы интерфейса
- **Профиль**: имя, email, аватар, статус сессии.
- **Лента**: карточки постов, кнопки открыть, лайк, комментарии.
- **Деталь поста**: текст, изображение, лайки, комментарии, кнопки редактировать/удалить для автора.
- **Редактор**: textarea, загрузка изображения, предпросмотр, кнопки сохранить/удалить.
- **Тосты**: уведомления об ошибках и статусе операций.

### Поведение UI (ключевые сценарии)
- **Авторизация**: после логина/регистрации токен сохраняется в `localStorage`, UI обновляет профиль и ленту.
- **Загрузка ленты**: `loadFeed()` получает данные из `/feed`, строит карточки постов.
- **Открытие поста**: `openPost(id)` получает детальные данные и комментарии.
- **Лайк/анлайк**: переключение состояния, обновление деталей и ленты.
- **Комментарий**: отправка формы, перезагрузка деталей и ленты.
- **Редактор**: определение режима (`new` или `edit`) по URL, подгрузка поста для редактирования.
- **Превью изображения**: `FileReader` показывает миниатюру и размер файла; удаление изображения устанавливает `remove_image=1`.

### Визуальные акценты
- Единый стиль карточек, мягкие тени и скругления.
- Фоновые декоративные элементы (`bg-orb`).
- Анимация появления элементов ленты (staggered effect).
